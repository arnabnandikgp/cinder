# Operating references

These describe implementation boundaries and preparation checks. They are not
current permission to create resources, use credentials, trade, move funds or
repeat an expired experiment. Start with [status](../status.md) and the selected
source/manifest; each live invocation requires its own approved scope and cleanup.

| Reference | Purpose |
| --- | --- |
| [Nitro qualification](nitro-qualification.md) | Attestation, key release, authenticated egress, protected state and exact-image checks |
| [Live qualification](live-qualification.md) | Chain/native provider boundaries, prerequisite evidence and explicit financial gates |
| [Unit deployment](unit-deployment.md) | Measured two-unit assembly, private configuration/agent separation and manifest constraints |
| [Unit qualification](unit-qualification.md) | Bounded SDK/native/read/admin acceptance and unsupported capability handling |
| [Dated receipts and proposals](../archive/README.md) | Actual historical source/image/outcomes, finite approvals and verified teardown |

Before any new run, verify current identity, resource ownership, allowed actions,
cost/time/request limits, exact source/image and cleanup path. Never reuse an old
ledger, expired capsule/policy, consumed native request or paper history to obtain
new authority. A financial failure remains a named failure even when safe direct
test teardown succeeds.
